# 顺序 × 布局联合搜索：主线设计的来由，与相关顶刊做法对照

> 2026-10-25。本次只查文献、不改代码。"核对程度"：**原文** = 读了相关章节；**摘要** = 只看了摘要或检索摘要，方法细节不据此推断。
> 前一轮（10-21）已调研过"运动代价/下界"方向，见 `idea/cost_innovation_20261021/literature/REPORT.md`；本文只补"顺序和布局怎么一起定"。

## 一、当前主线为什么这样设计（每个设计对应要解决的问题）

| 设计 | 解决什么问题 | 代码 | 文献上的依据 |
|---|---|---|---|
| **反向**（从最后装的零件往前定） | 第 k 步可不可行，只取决于第 k 步及以后零件的布局（更早的零件已装好或已拿走），所以不可行的后缀可以在定前面之前就删掉 | `search.py` | BLS 论文式 (11)；"拆卸求装配"（Tian TOG 2022、ASAP ICRA 2024） |
| **顺序在搜索中产生**（每层用 step_ok 找能拆的零件） | 顺序不是输入；能拆 = 两个状态静力稳定 + 能沿插入方向拔出 | `scene.step_ok` | ASAP、ORASP 都用"可拆性/先后约束"剪枝 |
| **一层里不同零件、不同布局一起排序** | 让"谁先装"由"这样装时最好的布局有多快"决定，而不是先定顺序再定布局 | `search.py:66–94` | 与 PCB"供料器分配 + 贴装顺序"联合求解的论点相同（分开求不能保证最优） |
| **状态 = (R, 已定后缀)，相邻两步用连接段耦合** | 不回 HOME，相邻零件的位置/抓取互相影响 | `expand.py` connection | Held–Karp 的 (集合, 最后一个) 状态 |
| **pend：前驱未知的那段取下界** | 定倒一时还不知道倒二是谁，先用所有可能前驱里最快的顶上，定了再换成真值 | `expand.py` pending | angelic 下界（ICAPS 2007/08）；ORLA* "缓冲位姿延迟决定" |
| **h(R)：剩余零件各自最乐观之和** | 让不同深度的节点可比 | `problem._bounds` | 可采纳启发；10-22 实测前几层排序很不准（Spearman −0.07） |
| **f_est 排序、beam 宽度 B、每零件 M、每位置 per_x** | 控制计算量，同时保留布局多样性 | `search.py` | beam search；BLS 也是 beam |
| **f_lb / g_lb 保留为下界** | 最后验证时 LazySP 式提前停止 | `validate.py:152–155` | LazySP、Multi-Bound Tree Search（下界剪枝） |
| **IK 目录（搜索前）+ GPU 碰撞（搜索中）** | IK 和状态无关只算一次；碰撞和状态有关现场批量查 | `screen.py`、`expand.py` | cuTAMP（GPU 批量粒子）；SEALP 是现场逐个算 |
| **最后用 cuRobo 真规划确认** | 下界/估计不等于能执行 | `validate.py` | BLS "完整布局正向全运动规划验证" |

## 二、相关工作按"定什么"分四类

### A. 顺序给定，只优化布局（大部分布局论文）
| 工作 | 核对 | 方法与工具 | 没做的 |
|---|---|---|---|
| Bachmann, Nottensteiner, Roa，ICRA 2021 | 摘要 | 约束非线性优化：最小化任务间行程 + 最大化可操作度；可达性、无碰撞约束；**遗传算法**；双臂装配铝型材 | 顺序固定；整体布局当一个候选评估 |
| Ali, Hu, Kiyokawa, Wan, Nishi, Harada，CASE 2025 | 题目/引用 | 任务和抓取约束下的 3D 工作单元布局 | 顺序固定（细节未读到） |
| Kawabe 等，IEEM 2022；EAAI 2025 | 摘要 | **sequence-pair** 编码避免重叠 + **NSGA-II**；**RRT\*** 算操作时间；代理模型约 98% 准确，计算时间约 1/400 | 不优化装配顺序 |
| Baumgärtner, Puchta, Fleischer，CIRP Annals 2025 | 摘要 | 布局优化里**直接用时间最优轨迹的时长**，指出几何/关节代理与周期时间差很大 | 无装配顺序 |
| Qiu 等，IJAMT 2022 | 引用 | 布局与轨迹同时优化（能耗、碰撞） | 无装配顺序 |
| Wachter 等，IFAC 2024；TU Wien（时间最优 TCP + 基座） | 摘要 | 并行优化器同时定基座与 TCP，考虑运动学/动力学限制，周期时间最多降 41–44% | 任务顺序给定 |
| **BLS（我们，arXiv 2608.18454）** | 原文 | 反向按装配顺序逆序分配初始位姿；局部可行性检查 + 碰撞掩码 + 候选过滤 + beam；正向全运动规划验证 | 顺序给定；代价是 TCP 路程 |

### B. 布局给定，只优化顺序（装配序列规划）
| 工作 | 核对 | 方法与工具 | 没做的 |
|---|---|---|---|
| Tian 等 "Assemble Them All"，TOG 2022 | 引用 | 基于物理仿真的"拆卸求装配" | 不考虑零件初始布局 |
| Tian 等 ASAP，ICRA 2024 | 摘要 | 重力下部分装配体稳定（少量零件被夹持 + 支撑面）；**树搜索**，启发可用几何规则或 **GNN**（用仿真标签训练）；数百个装配体数据集；仿真 + 实机 | 不考虑初始布局 |
| Nagpal & Mehr ORASP，IROS 2024 | 摘要 | **MDP + 动态规划**求最优策略；先后约束转成剪枝；大结构用**深度强化学习**；开源 | 不考虑布局与机器人运动时间 |
| Kiyokawa 等，RAS 2025 | 引用 | 仿真可行性 + 稳定性 + 多目标优化（半自动拆卸） | 无布局 |
| Chen, Wan, Koyama, Harada，T-ASE 2022 | 引用 | 双臂、不稳定中间状态的积木搭建：顺序 + 抓取 + 装配方向 + 支撑抓取 | 无初始布局 |
| Wan & Harada，ROBOMECH 2016 | 摘要 | 先枚举装配顺序，再对每个顺序增量建 regrasp 图（初始/放置/目标三层）递归找取放动作 | 只两零件；布局不是变量 |

### C. 顺序和位置一起定（和我们最像）
| 工作 | 核对 | 方法与工具 | 和我们的关系 |
|---|---|---|---|
| **ORLA\***，arXiv 2309.13707 | 前轮原文片段 | 移动操作臂整理：**lazy A\***；物体放到缓冲区时**先不定缓冲位姿，等它离开缓冲区再选代价最小的位姿**；在其离散域内全局最优（依赖稳定性预测正确） | 正是"等下一个定了再定这个"的思路，对应我们的 pend |
| Running Buffer（Gao, Feng, Huang, Yu；RSS 2021 / 2023 扩展） | 摘要 | 最少缓冲问题 NP-hard；**精确 DP**（百级物体）+ **ILP 基线** | 用精确解作对照 |
| TRLB（Gao 等） | 题目 | 缓冲位姿**惰性验证** | 和我们 lazy 验证同构 |
| Dynamic Buffers，arXiv 2509.22828 | 摘要 | 临时堆叠整体移动；PyBullet 39/40，实机 18/20 | 代价 = 行程 |
| Toussaint & Lopes **Multi-Bound Tree Search**，ICRA 2017（LGP） | 二手描述 | 离散动作树 + 连续优化；用**一系列松弛问题的可行性作下界**，便宜的先查，剪掉后再解完整非线性规划 | 我们算了 f_lb 但没用来剪枝 |
| Hartmann 等，T-RO 2023（建筑装配） | 摘要 | 找可行装配顺序 + 多机器人路径；分解成子问题迭代；优化（操作约束）+ 双向时空采样规划；实机 | 多机器人；不优化初始布局 |
| cuTAMP（Shen 等），RSS 2025 | 摘要 | 回溯搜索计划骨架；每个骨架一个连续约束问题，**GPU 并行采样 + 优化成批粒子** | 与我们"IK 目录 + GPU 批量"同类工具 |
| 检测单元"任务放置 + 顺序"，Robotica | 摘要 | 连续相机位姿 + 离散检测顺序，**组合粒子群** | 单件、非装配 |
| ABB 三阶段 | 摘要 | 逐个放 → 排序 → **模拟退火整体微调** | 有"离散后连续微调"一步 |
| RoboTSP（arXiv 1709.09343）；ProSeqqo（Kovács 等） | 摘要 | 每个目标的**多个 IK 解当一个簇**（GTSP，每簇选一个）；分解求解 | 我们每个位姿只留 1 个 IK |

### D. 运筹学里结构相同、且有精确方法的问题
| 问题 | 核对 | 方法 | 对应 |
|---|---|---|---|
| PCB 贴装：供料器分配 + 贴装顺序 | 摘要 | 分别是 QAP 和 TSP/VRP，都 NP-hard；有论文主张**必须同时求**；MILP + 混合进化算法；JORS 2006 给出联合问题的**下界** | 供料器位置 = 零件初始位置；贴装顺序 = 装配顺序 |
| 仓储：库位分配 + 拣货路径（SLAPRP） | 摘要 | **分支-割-定价（branch-cut-and-price）**精确算法，扩展公式的对偶界显著好于紧凑 MIP；中等规模可解到最优 | 同上 |

## 三、这些工作做了、我们还没做的事

1. **有精确解或证明的最优性差距。** ORLA\*（离散域内最优）、Running Buffer（精确 DP + ILP）、SLAPRP（分支-割-定价）都能给出"离最优多远"。我们的 beam 没有任何最优性证据。
2. **用下界真正剪枝。** Multi-Bound Tree Search 用一串松弛问题的下界逐级剪枝；我们的 f_lb 算了没用。
3. **延迟决定。** ORLA\* 把缓冲位姿的选择推迟到下一个动作确定之后；我们用 pend 估计，但已排序淘汰的布局不会回头。
4. **多个 IK 解作为可选项。** RoboTSP/ProSeqqo 把每个目标的多个 IK 解都留作候选；我们只留 1 个。
5. **学习型启发。** ASAP 用 GNN、ORASP 用 DRL 指导顺序搜索；我们的 h(R) 是手写下界，前几层排序很弱。
6. **直接用真实时间评估布局 / 代理模型。** Baumgärtner 直接用时间最优轨迹；Kawabe 用约 98% 准确的代理。我们用下界 + 绕路惩罚，只在最后懒验证。
7. **离散搜索之后的连续微调。** ABB 第三阶段、TU Wien 并行优化器、SEALP 的 yaw 细化；我们没有。
8. **规模和实机。** ASAP 用数百个装配体；BLS 用 5 个模型；我们目前主要是三角框架一个场景，实机尚无。
9. **更完整的物理可行性。** ASAP 考虑夹持零件数量和支撑面；我们只有静力 LP + 插入扫掠。

## 四、怎样证明结果是正确的、好的

### 1. 正确性（计划确实能执行）
- 每个输出计划都用**完整运动规划**确认（已有：cuRobo witness）。
- **独立检查器复查**：用和搜索不同的碰撞模型（WRS 网格）再查一遍全计划（`joint_search/wrs_check.py` 已有雏形）。
- **物理仿真或实机执行**：稳定性用物理引擎（ASAP 用仿真标签），最后上实机。

### 2. 最优性（离最好还差多少）
- **小实例精确解**：同一代价模型、同一离散候选，用穷举 DP/A\*（状态 = (R, head, 桌上位置集合)）求真正最优，报告 beam 的差距。三角框架 6 个零件，若每零件候选缩到 5–8 个，可做。
- **上下界差距**：搜索结束时，所有被删节点的 f_lb 的最小值，就是"任何没搜到的计划都不可能低于它"的界；报告 (最好可执行时间 − 这个界) / 这个界。
- **独立公式交叉验证**：极小实例写成 MILP 或 CP-SAT，用求解器的最优值核对 DP。

### 3. "联合"到底值多少（必须有的对照组）
- **固定顺序 + 布局搜索**（SEALP/BLS 的设定）：顺序取 ① 随机可行顺序 ② 启发式顺序 ③ 所有可行顺序里最好的那个（三角框架只有 48 个稳定顺序，可以全试，这是"顺序和布局分开但都求到最好"的强基线）。
- **两阶段**：先只按顺序代价排出顺序，再定布局。
- **交替优化**：固定顺序优化布局 ↔ 固定布局优化顺序，迭代到不变（PCB、SLAPRP 文献的标准对照）。
- 所有方法**同样的计算时间**，比较 cuRobo 确认后的执行时间。

### 4. 消融和稳健性
- 去掉 pend、去掉 h(R)、B/M 变化、网格疏密、姿态 first/best、cost 用下界还是估计值。
- 多个场景（frame、rack10、armchair、tower……）、多个随机种子（MorphIt 拟合有随机性），成对比较用 Wilcoxon 符号秩检验。
- **排序保真度**：f_est 与最终真实时间的 Spearman/Kendall，以及排序遗憾。
- **任意时刻曲线**：给定时间内能达到的最好时间。

## 五、对"倒一要等倒二定了再算"这个问题，文献怎么做
- **Held–Karp 动态规划**：状态 = (已访问集合, 最后一个)，相邻两步的代价在转移时精确计算，等价于我们的 (R, head)。
- **angelic 下界**：对未知前驱取最小值，就是我们的 pend；它是可采纳的。
- **ORLA\* 的延迟决定**：被影响的那个决定先不做，等相邻决定出现后再一起选最优。对应的改法：第一层只定"倒一是谁 + 抓取"，桌面位置等倒二定了再选（位置只影响拿取段和"倒二→倒一"的连接段）。
- 这些都说明我们的设计方向与文献一致，可改进的点是：排序过早淘汰（加分组保底或延迟决定）和状态合并（按 (R, head, 桌上位置集合) 合并）。
