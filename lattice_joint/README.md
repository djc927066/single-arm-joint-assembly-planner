# lattice_joint：在"已装集合网"上精确联合搜索装配顺序 × 初始布局

2026-11-02 起作为主线。旧主线 `joint_search`（反向 beam 搜索）保留不动，它的 IK 目录、碰撞检查器和 cuRobo 验证由这里复用。
来源是实验 `experiments/bls_all_orders_20261031/lattice_search.py`，实验目录里的文件也都保留。

```powershell
python -X utf8 -m lattice_joint.run                                # 三角框架，逐步打印
python -X utf8 -m lattice_joint.run --model twin10 --quiet         # 每 2 万步打印一次进度
python -X utf8 -m lattice_joint.run --model twin10 --quiet --no-prices --cap 2000000   # 不用桌面定价，对比用
```

输出：`lattice_joint/_output/<model>.json`，包含顺序、布局、统计，以及停止时没展开的分支。

```powershell
python -X utf8 -m lattice_joint.validate                           # 对上面的结果做 cuRobo 验证
```

验证（`validate.py`）的步骤：
1. 每一步选一个抓取：在搜索认可的可用抓取里，用小动态规划选关节时间下界最小的组合；
2. 用 `joint_search.validate.Validator` 验证：空手、搬运、回 HOME 三类自由段都交给 cuRobo 规划，直线可走就走直线；然后用 WRS 网格检查整个执行过程，包括下降、抓取、抬起、插入、松手、撤离；
3. 某一步不通过时，禁掉那一步的抓取再选，最多试 `--tries` 次。

## 筛选与验证一致（2026-11-02）

实验版本的球体筛选（沿用 joint_search.expand）有两处跳过不查，导致最终方案过不了网格验证：
- 下降的最后 25%、抬起的最初 25%、松手撤离的最初 25%，**所有障碍物都不查**。三角框架里 beam_CA 摆在装配底座旁边，下降时手指碰到了底座。
  - 现在这几段用球体检查"除桌子和手上这个零件之外的一切"（底座、已装零件、桌上其他零件），在一个去掉桌子的碰撞世界里查（`world_no_table`），仍然是 GPU 批量检查。
- 手指和**正在抓或正在松开的零件本身**之间没有检查。beam_CA 斜着装，部分抓取松手后撤离时，手指会擦到 CA。
  - 现在用网格检查（`mesh_self_checks`）：下降和抓取按（零件，摆放朝向，抓取）检查，松手和撤离按（零件，抓取）检查。手和零件的相对位置与摆在哪、装了什么无关，所以每个场景只算一次（三角框架 33 秒），结果缓存在 `lattice_joint/_cache`。不通过的抓取在每个位置选 k 个抓取之前就去掉。
  - `--no-self-mesh` 可以关掉这项检查，恢复实验版本的行为。

## 桌面定价下界和抓取筛选（2026-11-07）

- `prices.py`：桌面上一个点最多被一个零件盖住。给桌面点定价，把价钱加进 F 的单步代价，最后减去价钱总和，得到的仍是下界（拉格朗日弱对偶）。每个未定集合 R 单独调价，搜索取原下界和定价下界中较大的值。`--no-prices` 关掉。
- `LatticeSearch.dive`：反向贪心得到第一个完整方案，作为搜索的初始 U。
- `mesh_seat_checks`：抓取还要用网格检查插入、松手、撤离时不碰底座和“一定已经装好的零件”。球体模型在这里太粗。
- 基准模型的底座原点在厚度中心，`Instance.default_center` 会把装配中心 z 设为半个底座厚度，否则装配体陷进桌面。
- `--min-free-gb`：可用内存低于这个值时停止搜索。

## 问题

- **决策**：装配顺序（稳定顺序之一），以及每个零件的初始桌面位置（候选之一）。
- **约束**：每一步都要存在一个可用的抓取：
  - 桌上抓取（悬停、抓取、抬起）不撞桌子、底座、已装零件和桌上其他零件；
  - 用同一个抓取在目标处插入、撤离，也不撞这些东西；
  - 桌上零件的占地互相至少隔开 1 cm。
- **代价**（chain，欧氏距离；点取零件原点，"上方"指 z + 0.10 m）：
  ```
  每一步 = |上一件的目标上方 → 这一件的抓取点上方|（第一件从 HOME 出发）
         + 0.10（抓取）+ |抓取点上方 → 目标上方| + 0.10（插入）
  最后加 |最后一件的目标上方 → HOME|
  ```

## 五个步骤

| 步骤 | 文件 | 做什么 |
|---|---|---|
| 0 | `instance.py` | 场景、候选位置、IK 目录、碰撞检查器沿用 `joint_search.problem.Problem`；列出稳定顺序；每个位置保留 k = 8 个抓取 |
| 1 | `lattice.py` | 状态网：节点 = 已装集合，箭头 = 再装一个零件。对每条箭头 S —p→ 算一次 **D(S, p)**：p 的桌面位置里，只看已装集合 S 时有可用抓取的那些 |
| 2 | `lattice.py` | 箭头代价 step(S, last, p) = 在 D(S, p) 里取上式最小的位置；**从前往后**做动态规划，得到 F(S, last)：从 HOME 装完 S、最后一件是 last 的乐观代价。全网最小值就是下界 |
| 2b | `prices.py` | **桌面定价**：对每个未定集合 R，用次梯度法调桌面点的价钱，得到“装完 R”的更紧下界，存在 `Lattice.sub`。同时用 `LatticeSearch.dive`（反向贪心）得到初始方案 U |
| 3 | `search.py` | **反向最好优先搜索**。节点 =（还没定的 R，已定后缀的零件和位置，后缀真实代价 g）。分数 f = g + 这一步的真实代价 + 连到后缀第一件的真实代价 + 前缀的乐观值（F 下界和定价下界取大，且不低于父节点的 f）。每次取 f 最小的；位置按 f 排队，**取到时才检查**它是否被桌上的后缀零件挡住；f ≥ U 的项不进堆 |
| 4 | `search.py` | 得到完整方案就更新 U。R、后缀第一件及其位置、后缀各零件位置都相同的节点只留 g 最小的一个（合并，不影响最优） |
| 5 | `search.py` | 堆顶 f ≥ U 时停止，此时 U 是离散候选下的最优。最后按坐标把这个方案的代价重算一遍核对 |

为什么下界成立：
- 直线是最短的移动；
- D(S, p) 包含真实方案里所有可用的位置（真实方案还要避开桌上的零件，只会更少）；
- 在 D(S, p) 里取最小。

所以 F 不会高于任何真实前缀的代价，用它剪枝不会丢掉最优解。定价下界成立是因为：真实方案里零件占地互不重叠，每个桌面点最多付一次价钱，所以“代价 + 占地费 − 价钱总和”不超过真实代价。

## 和 joint_search 的区别

| | joint_search（旧主线） | lattice_joint |
|---|---|---|
| 搜索 | 反向 beam：每层留 B = 10 个，每次扩展留 M = 10 个，不保证最优 | 反向最好优先 + U，保证最优（离散候选下） |
| 下界 | h(R) = 每个零件最小值相加，不管顺序 | 网上的 F，考虑顺序和已装集合 |
| 几何 | 每次扩展检查所有（位置，抓取） | 按分数排队，取到才检查 |
| 代价 | 关节时间；被挡段乘修正系数，最后用 cuRobo 确认 | 欧氏距离 |
| 抓取 | 决策变量 | 可行性条件（存在一个即可） |
