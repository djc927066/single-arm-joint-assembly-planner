# joint_search：反向联合搜索装配顺序、初始布局与装配抓法

第一版，2026-10-16。三角框架（6 个零件，48 种静态稳定顺序，每个零件 40 个候选位姿、8 种装配抓法），桌上只有零件做障碍。

```powershell
$py = 'E:\Projects\wrs-sealp-assemble\dual_sealp\cuRobotest\.venv\Scripts\python.exe'
& $py -X utf8 -m joint_search.run_frame --B 10 --M 5 --N 5
```

## 问题

- 决策：顺序 π（稳定顺序之一）；每个零件的初始位姿 x（候选之一，桌面占地互相至少 1 cm）；每个零件的装配抓法 g。
- 执行：HOME → 取第 1 件 → 装 → 不回 HOME，直接去取第 2 件 → … → 装第 6 件 → 回 HOME。
- 目标：整条执行时间（各关节速度、加速度受限，静止到静止）

```
每一步 = 空手段 [上一件撤离(g) 或 HOME → 悬停(x,g)]
       + 短段 [悬停 → 准备抓取 → 抓取 → 抬起] + [插入前 → 插入 → 撤离]
       + 携物段 [抬起(x,g) → 插入前(g)]
最后加 回 HOME 段 [撤离(最后一件) → HOME]
```

## 为什么反向

正向第 k 步：前 k−1 件已装（在装配位），后面的零件还在桌上（在各自的初始位姿），第 k 件在 x_k。反向搜索先定后面的零件，所以定第 k 件时，**桌上有哪些零件、在哪里，已装的是哪几个（集合），全部已知**，这一步的障碍环境是确定的。唯一未知的是"机械臂从哪来"（上一件是谁、用什么抓法），这一段留到下一次扩展再算。

## 节点（`search.py`）

| 字段 | 含义 |
|---|---|
| R | 还没决定的零件（正向时比已定后缀先装，顺序未定） |
| suffix | 已决定的步骤（零件, 位姿, 抓法），按正向顺序 |
| head | 后缀第一个零件及其 (位姿, 抓法)：**接口状态**，它的空手段起点还悬空 |
| table | 后缀零件的初始位姿（它们在前面所有步骤中都在桌上） |
| g_lb / g_est | 已确定各段的下界 / 估计（下界 + 被挡程度修正） |
| pend | head 悬空空手段的下界 |

`f_lb = g_lb + pend + h(R)` 不高估（剪枝用）；`f_est = g_est + pend + h(R)` 用于排序和束选择。`h(R)` 是离线表：每个零件"任何位姿、任何抓法、任何起点"下最少要花的时间之和（`problem.py`）。

## 一次扩展（`expand.py`）

选 p ∈ R 作为"R 里最后装的"，对它所有 (x, g) 一起算：

1. 合法性：装 p 前已装 R\{p}，要静态稳定；x 不和后缀零件占地重叠；HOME 姿态不撞 p。
2. 世界 A（已装 R\{p}，桌上后缀零件，p 在 x）：悬停、准备抓取、抓取、抬起、插入前姿态，垂直下降、竖直抬起，手持零件撞手臂；携物段直线 + 被挡程度。
3. 世界 B（已装 R，含 p；桌上后缀零件，head 作为要抓的零件）：撤离姿态，以及**撤离(g) → head 的悬停点**（根节点时是 → HOME）。这一段把 head 的悬空空手段确定下来。
4. 如果 R\{p} 为空（p 是第一件）：HOME → 悬停(x, g) 也在世界 A 里检查。
5. p 自己的空手段起点未知：下界 = 对所有可能紧挨在 p 前面的零件和它们的抓法，撤离 → 悬停(x, g) 的最小关节时间。

每段：直线没被挡 → 时间 = 下界（准确）；被挡 → 估计 = 下界 × (1 + 0.243 + 1.09 × 最大穿透深度[m])（`lazy_cost/penalty.py`，用新计时下"只有零件"的实验拟合）。

## 束搜索

- 每次扩展，每个 p 保留 f_est 最好的 M 对 (x, g)，同一位姿最多保留 2 种抓法（保留布局的多样性）；
- 每层保留 f_est 最好的 B 个节点；R 和后缀完全相同的节点合并；
- R 为空时得到完整方案。

## 最后确认（`validate.py`，搜索层面的惰性）

1. 完整方案按"顺序 + 布局"去重，取估计最好的 N 个；
2. 按估计从小到大：直线可走的段 = 下界；被挡的段用 cuRobo（轻量轨迹优化）规划，按 TOPP 计时，结果缓存；
3. 已确认的最好方案 ≤ 剩余方案的下界时停止；
4. 选中的方案每一段都用 cuRobo 规划一遍（可行性见证）；直线可走的段按直线执行，其余按 cuRobo 路径执行。

## 过程中修掉的两个问题

- **计时**：原来的 `curobo_bridge.assembly_demo.topp` 对弯曲路径把切向和拐弯加速度分开限制，关节实际可达约 2 倍加速度，算出的时间可能低于下界（0.42 s vs 下界 0.60 s）。改用 `lazy_cost/timing.py` 的 TOPP（每个关节合并约束），直线时等于下界、弯曲时不低于下界。**之前 lazy_cost 实验里被挡段的真实时间因此被低估了 2–27%，修正系数需要用新计时重新拟合。**
- **cuRobo 规划器的残留障碍**：`BatchMotionPlanner.update_world` 移除障碍后，它的几何仍在起作用（`clear_scene_cache` 无效）。现在切换世界前先 `enable_obstacle(name, False)`（`lazy_cost/refine.py`）。我们自己的碰撞检查器没有这个问题。
